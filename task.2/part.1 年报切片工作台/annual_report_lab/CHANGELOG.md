
## v3 — MD&A 语义切分与结构化 PDF

- 管理层讨论与分析不再绑定“第X节”或固定序号；支持任意标题层级和“经营层讨论与分析”等别名。
- 新增 MD&A 内部条目簇兜底，标题抽取损坏时仍可反推章节范围。
- 新增 `core/pdf_slice.py`，从原 PDF 精确裁切首尾页，保留段落、表格、图片和矢量结构。
- MD&A 任务成为主成功标准；其余三类切片保留兼容，但不再导致主任务失败。
- 章节文件统一使用 `股票代码_公司简称_年度_章节名` 命名。
# 改动说明（annual_report_lab v2.1）

对照你提的五条需求，逐条说明改了什么、改在哪、怎么验证。

---

## 需求 1 · 管理层讨论与分析按整节切

**原来的问题**：`locate_chapters()` 用动态规划挑一条"最小间距最大"的节序列，MDNA 的终点
取的是"DP 选中的下一个序号章节"。序号缺失、页眉重复、正文里出现"详见第四节"时，
终点会跳到错误的位置，整节被截断或吃掉下一节。

**现在的做法**（`core/slicer.py`）：

| 环节 | 函数 | 说明 |
|---|---|---|
| 标题解析 | `build_headings()` | 逐行判断是不是标题，序号独占一行时与下一行合并 |
| 目录剔除 | `detect_toc_ranges()` | 点线成簇 / "目录"后序号连续递增的一串 / 节标题异常密集 |
| 节序列 | `select_body_chapters()` | 每个序号取**第一次**出现且在上一节之后的那次 |
| 整节切出 | `slice_report()` | MDNA 终点 = **下一个节标题的位置**，中间条目全保留 |

- 页眉里重复的同一节标题被自动忽略（同序号只取一次）；
- 某一节没识别到不影响——上一节区间只会延伸到下一个识别到的节，这正是
  "到下个标题之前"的语义；
- 整节异常短（且全文 > 5 万字）时判定为被页眉或交叉引用截断，自动顺延一节并写日志；
- 识别方式字段写明"至第4节「公司治理」之前"，边界可追溯。

## 需求 2 · 研发投入按小节切，「不适用」单独汇报

**切片**：只在 MDNA 范围内找（找不到才扩到全文，且只接受高分命中），
终点 = 下一个**同级或更高级**标题（`（五）研发投入` 的下一个是 `（六）…` / `五、…` / `第四节`）。
同时记录它挂在哪个上级条目下（`parent_title`，如"四、主营业务分析"）。

**三种结局分开记**（`detect_not_applicable()` + `_rd_status_label()`）：

| 结局 | 判定 | 去处 |
|---|---|---|
| 已切出（有内容） | 小节存在且有实质内容 | `研发投入.txt` |
| 公司填报不适用 | 正文只有"不适用/无"；或勾选 `□适用 √不适用`；或 `是否适用 □是 √否` | 文件头写明依据 · 结果表「研发投入是否不适用」列 · Excel「研发投入-不适用」表 · 日志与 CLI 汇总单独汇报 |
| 小节缺失 | 年报里根本没有这个小节 | 结果表「研发投入情况」列 · Excel「研发投入-缺失」表 · 日志汇报 |

勾选框方向：`√适用 □不适用` 是**适用**，`□适用 √不适用` 才是不适用；
"本项目不适用于合并范围外主体"这种句中词不算。

## 需求 3 · 业务概况改用 deepseek-v4-pro 概括

`core/ai_assist.py` 的 `summarize_business()`。规则切不出来时触发，
把已切好的 MDNA 全文（必要时叠加核心竞争力章节）交给**高级模型**，按固定 JSON 结构概括：

> 一句话定位 / 所处行业与行业趋势 / 主营业务与主要产品服务 / 经营模式（研发·采购·生产·销售·盈利）
> / 主要客户与销售区域 / 行业地位与竞争格局 / 报告期业务进展 / 核心竞争力 / 主要风险
> / 关键经营数据 / **年报未披露的条目**

提示词四条硬性要求：只依据给定原文、禁止外部知识与推测、原文没写的一律写
「年报未披露」并在最后一项列出、每个数字必须能在原文原样找到。
超过 26000 字时头尾取样（业务与行业在开头、展望与风险在结尾，中间多是财务明细表），
并在识别方式里标注。

**产出的是 AI 文本不是原文**，所以做了四处标注：文件头 ⚠ 警示 + 生成模型名、
结果表「业务概况来源」列、Excel 单开「业务概况-AI概括」表、矩阵里半透明虚线小条 + 抽屉 ✎ 标记。

模型名服务端不认时按 `DEEPSEEK_MODEL_FALLBACKS` 依次降级并写日志，不会整轮任务作废。

## 需求 4 · 切片后验

新增 `core/verify.py`，在规则切片、AI 补定位、业务概况概括**之后**执行。

| 切片类型 | 检什么 |
|---|---|
| 普通切片 | start_ok（是否正好从标题行开始）/ end_ok（是否停在下一个同级标题之前）/ content_match / complete（有没有从中间截断） |
| 「不适用」切片 | 复核公司是不是真填了不适用；判错会被推翻，状态改回普通切片并标"请人工确认" |
| AI 概括的业务概况 | 不查边界，改查幻觉——列出所有原文不支持的表述，有一条即判 fail |

**自动修正是保守的**：模型只能给"原文引文"当新边界，程序必须在限定窗口里精确找到该引文
（找不到就退一步在压缩空白后的串上再找一次），且修正后长度不得超过原切片的 3 倍
（`AI_VERIFY_MAX_EXPAND_RATIO`）。任何一项不过就**放弃修正、只留警告**——
最坏情况是"没修成"，不会是"正文被改写"。

结论落在：结果表「后验结论 / 后验逐章节 / 后验问题」三列 + 每章节「·后验」列、
`_meta.json` 的 `verify` 字段、切片文件头；存疑或失败的任务状态降为**需复核**，
Excel 单开「后验存疑」表。

## 需求 5 · 不再单纯相信关键词

**这是最根本的一处改动。** 原来是"在全文里搜关键词，谁先出现算谁的"，
所以"公司持续加大**研发投入**力度"这种正文句子会被当成小节标题；
`_loose()` 里那个"找到关键词就截取其后 8000 字"的兜底更是直接放大了误差。

现在关键词只在**标题行**上匹配，而且要打分（`score_title()`）：

| 情形 | 分数 |
|---|---|
| 标题与规则完全相等 | 100 |
| 标题后面只多几个字（"研发投入情况"） | 82 |
| 标题略长（≤30 字） | 66 |
| 标题与正文粘在一行 | 44 |

再叠加规则优先级；无序号标题 −18，与正文粘连 −12。
**≥55** 记为精确切出，**38–55** 记为"疑似（待复核）"并交给 AI 后验，**<38** 直接不采纳。
`_loose()` 那条 8000 字兜底已删除，区间一律由相邻标题决定。

另外还挡掉两类常见误判：`第X节` 前面是汉字的（"详见第四节财务报告"）不算标题；
目录区整体屏蔽，不参与任何匹配。

## 需求 6 · 读取历史成果与断点续跑

新增两层持久化机制：

1. **每任务检查点**：`.state/tasks/<股票代码>_<年度>.json`。任务进入 `RUNNING` 时写一次，
   结束时再写一次，全部采用临时文件 + `os.replace()` 原子替换；
2. **整轮清单**：`manifest.json` 仍保留，同时自动备份上一版为 `manifest.json.bak`。

启动时 `Store.load_resume_records()` 会合并三类来源：manifest、任务检查点、
旧版本已经存在的 `sections/**/_meta.json`。因此旧程序即使在最终 manifest 写出前中断，
新版本也可以从章节目录反向恢复已完成成果。

恢复规则：

- `OK` / `PARTIAL` 且所有已切出章节文件仍存在 → 直接复用，不联网、不调用 AI；
- `RUNNING` / `STOPPED` / 失败状态 → 自动重新执行；
- 重执行时优先按股票代码和年度查找已有 PDF 与全文，简称变化也不会导致重复下载；
- Web 默认勾选“自动读取已有成果并断点续跑”；CLI 默认开启，可用 `--no-resume` 关闭；
- “强制重新下载”与“重跑异常项”会明确绕过完成状态，按用户要求重做。

章节预览也改为优先读取历史记录中的真实 `section_files` 路径，避免恢复后因公司简称变化
导致页面找不到旧目录。

## 升级注意事项

1. **文件名变了**：`业务概要.txt` → `业务概况.txt`（按你的说法统一）。
   如果下游脚本按旧文件名读，需要一起改。
2. **结果表新增列**：研发投入情况、研发投入是否不适用、不适用依据、业务概况来源、
   后验结论、后验逐章节、后验问题、切片提示，以及每章节的「·状态」「·后验」两列。
   Excel 从 2 张表变成 6 张表。
3. **状态码语义微调**：`PARTIAL` 的显示名从"章节缺失"改为"**需复核**"——
   现在它也包含"后验存疑"的情况。研发投入填"不适用"、业务概况由 AI 概括，
   都**不再算缺失**。
4. **AI 开关拆成三个**：启用 DeepSeek（总开关）/ 业务概况 AI 概括 / 切片 AI 后验，
   页面与 CLI（`--deepseek-key` `--advanced-model` `--no-ai-summary` `--no-verify`）都有。
5. **输出目录现在包含隐藏的 `.state` 目录**：不要在批跑途中删除它；
   即使删掉，程序仍会尽量从 `manifest.json` 和章节 `_meta.json` 恢复。
6. **建议先小批量试跑**：拿 3~5 家公司、开着后验跑一轮，
   看「后验存疑」表和日志里的"切片提示"，确认版式假设在你的样本上成立，再批量跑 72 家。
