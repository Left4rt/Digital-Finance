# 招聘信息结构化抽取 —— 人工标注规范 v1.1

## 0. 标注对象
标注对象为 `data/sample20.json` 中的 `input_text` 字段，即
「职位：{title}」+「【职位描述】{jd 正文}」两部分构成的招聘原文。
**不得参考原始 CSV 中的 salary / location / experience / degree 等结构化列**，
这些列仅用于事后交叉核对与误差分析。

## 1. 最高原则：证据可溯
> 标准答案中的每一项，必须能在 `input_text` 中找到**字面依据**。
> 原文未写的一律标 `null`（标量字段）或 `[]`（列表字段），**不得用常识补全**。

典型反例（禁止）：
- 岗位叫「AI 实习生」→ 就补 `PyTorch / TensorFlow`；
- 岗位是 Java 后端 → 就补「团队协作能力」；
- 出现「大数据」→ 就归入「AI 相关技术栈」。

## 2. 字段定义

| 字段 | 定义 | 缺省值 |
|---|---|---|
| 职位名称 | 「职位：」行给出的岗位名称，原样保留（含括号后缀） | null |
| 薪资范围.最低薪资 | 原文出现的薪资下界，保留原始单位 | null |
| 薪资范围.最高薪资 | 原文出现的薪资上界 | null |
| 薪资范围.薪资周期 | 「月」/「年」/「日」/「13 薪」等计薪周期 | null |
| 工作地点 | **明确声明的办公地点**（城市/区县/园区） | null |
| 技能要求.硬技能 | 可客观验证的技术与业务技能：编程语言、框架、库、工具、数据库、中间件、操作系统、架构与平台技术、算法方法、专业业务技能、执业资格证书 | [] |
| 技能要求.软技能 | 个人特质类能力：沟通、协作、学习、抗压、责任心、主动性、逻辑思维、执行力等 | [] |
| 学历要求 | 学历层次要求（含「统招/全日制/在读」等限定语） | null |
| 经验要求 | 工作年限或明确的经验要求 | null |
| AI相关技术栈要求 | 原文明确出现的 AI/ML/DL/大模型相关**技术、框架、工具、模型类别**名词 | [] |

## 3. 边界规则（消歧）

**R1 技能标签块**
爬取的 JD 正文顶部常含站点技能标签（每行一个词）。这些标签属于招聘原文的一部分，
**计入标注**；标签与正文重复的项去重。

**R2 地点线索 ≠ 工作地点**
仅当原文以「工作地点/办公地点/此岗位在 X」等方式明确声明时才填写。
- J06「1.工作地点：海淀」→ `海淀` ✅
- J10「有意愿在常州地区发展优先考虑」→ 求职意愿偏好，非办公地点声明 → `null`（记入歧义清单）
- J11 职位名称含「(济南恒丰岗)」→ 岗位名称已字面指明济南 → `济南` ✅（记入歧义清单）

**R3 「优先/加分项」的处理**
- 「优先」出现在**学历/经验**上时，仍填入该字段，但保留「优先」字样
  （J07「硕士及海外留学背景优先」→ 学历要求 = `硕士优先`）。
- 「优先」出现在**技能**上时，正常计入技能列表（它仍是原文明确出现的技能名词）。

**R4 任务名 vs 技术名**
「文本分类」「意图识别」「情感分析」等是**任务**，不计入 AI 技术栈；
「PyTorch」「深度学习」「大模型」「AI Agent」「MCP」等是**技术/框架/范式**，计入。
硬技能列表则可收录任务型专业技能（如「数据标注」「数据迁移」）。

**R5 AI 技术栈是硬技能的子集**
同一项若属于 AI 技术（如「机器学习」），需**同时**出现在 `硬技能` 与 `AI相关技术栈要求` 中。

**R6 大数据 ≠ AI**
Hadoop / Hive / Spark / Kafka / 数仓 归入硬技能，**不**归入 AI 技术栈。
除非原文另有 AI 字样（如 J05 的「AI Agent、MCP」）。

**R7 冲突值**
标签块与正文冲突时，以**正文**为准，标签值登记为「可接受别名」。
- J11：标签「2-8年工作经验」vs 正文「5年以上开发经验」→ GT 取 `5年以上`，
  `2-8年` 计入别名表，模型输出任一均判正确。

**R8 归一化**
大小写、全半角、`/` 与 `、` 分隔符差异不影响判定，由评测脚本的 `normalize()` 处理；
语义等价（如 `OC` ≡ `Objective-C`、`本科及以上` ≡ `本科以上`）由 `eval/alias_table.json` 处理。

## 4. 标注流程
1. 标注员 A 依据本规范逐条标注（第一遍）；
2. 间隔后进行**第二遍自查复核**，重点核对 `null` 判定与 AI 技术栈边界；
3. 两遍不一致处记入 `data/ambiguous_cases.md`，并据此补充规则 R2/R3/R7；
4. 冻结 GT，评测阶段不得再修改。

> 说明：本实验为课程设计规模，采用单标注员 + 二次复核，未做双人 Kappa 一致性检验。
> 若扩展到 100 条以上样本，建议引入第二标注员并报告 Cohen's Kappa。
